Intro comparison: does not match

2026-10-15 · Original ROM played from boot through the title in PyBoy 2.8.1 (CGB mode, built-in boot ROM, no button input). Java frames rendered with the current checkout’s IntroSequence, GPU and GameFrameSceneBuilder, using the same ROM and the existing DumpIntroFramesHarness rendering approach.

13 reproducible random samples, stratified across six intro phases, seed 20261015. All 13 differ. This is a visual validation result; no gameplay source was changed.

Confirmed differences

  • Storm: wave bands scroll differently, with different rain and lightning placement/phase.
  • Link close-up: initial background art matches closely, but the scream frame leaves Link’s mouth closed. The ROM’s IntroLinkScream queues a tilemap patch; Java changes its substate without applying that patch.
  • Beach fade: the original is still white at the sampled point; Java already shows the fully colored beach. The ROM enters the countdown with 0xFF, while Java uses 0xA0 and does not implement the corresponding fade palette progression.
  • Beach: background parallax, wave placement, and Marin/Link poses differ. Java derives Marin’s sprite variant from the state number; the original selects animated variants within each state.
  • Beach-to-title: Java skips the original upward camera movement and streamed background updates driven by InertLinkState2Handler.
  • Title: Java’s scene is displaced upward, with wrapped logo fragments at the bottom.

Comparison method and limits

Each pair uses the same elapsed offset from the corresponding phase entry. Phases are realigned separately so earlier timing drift does not invalidate later comparisons. This does not synchronize the RNG or interrupt phase, and later beach substates may diverge. Percentages measure observed full-frame differences, including timing and random effects; they are not isolated artwork error rates. RGB values are reduced to five bits per channel before comparison to remove RGB555 expansion differences. White pixels in the difference image indicate a mismatch.

The Java harness exercises the production CPU framebuffer path, not a captured desktop/OpenGL window. Audio and full GPU presentation were not assessed. No claim of exhaustive pixel accuracy is made from sampling.
